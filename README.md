# Towers

Towers добавляет еженедельные задания на калибровку одной из 16 вышек. После калибровки игрок определяет область через привязанный компьютер и отражает волны мобов в разломе; прогресс и расположение объектов сохраняются в SQLite.

## Требования и зависимости

- Paper API `1.21.7` или совместимое ядро с поддержкой этого API.
- Java 21.
- Обязательных зависимостей нет.
- `CustomMob` и `SkinPlugin` указаны как `softdepend`: они нужны для настроенных мобов CustomMob и наград-скроллов QUACK соответственно. Без них соответствующие записи мобов или скроллов использоваться не будут.
- Для отображения настроенных `item-model` и custom model data нужен совместимый ресурс-пак. Команда не устанавливает и не поставляет ресурс-пак.

## Установка и сборка

Скопируйте `Towers.jar` в каталог `plugins/` и запустите сервер. Плагин создаст `plugins/Towers/config.yml` и базу `plugins/Towers/database.db`; подключать отдельную базу данных не нужно. При первом запуске старые `players.yml`, `displays.yml` и `forced-chunks.yml`, если они есть, импортируются в SQLite; рядом создаются резервные копии с суффиксом `.sqlite-backup`.

Сборка из исходников Maven и Java 21:

```bash
mvn clean package
```

Готовый JAR: `target/Towers.jar`.

## Команды и права

Все подкоманды требуют `towers.admin` (по умолчанию `op`). Команда размещения объектов `spawn` доступна только игроку; тестовые действия также выполняются игроком.

| Команда | Описание | Permission | По умолчанию |
|---|---|---|---|
| `/towers reload` | Перечитать конфигурацию, обновить волны, эффекты мобов, объекты и расписание заданий. | `towers.admin` | `op` |
| `/towers refresh` | Немедленно обновить задания онлайн-игроков. | `towers.admin` | `op` |
| `/towers spawn <1-16\|central\|computer>` | Создать вышку, центральную вышку или компьютер рядом с собой. Компьютер привязывается к ближайшей нумерованной вышке. | `towers.admin` | `op` |
| `/towers remove <1-16\|central\|calibration\|chunk\|all>` | Удалить выбранную вышку и связанные объекты, категорию объектов либо все сохранённые объекты Towers. | `towers.admin` | `op` |
| `/towers give <player> <1-16>` | Выдать онлайн-игроку задание на указанную вышку. | `towers.admin` | `op` |
| `/towers reset <player>` | Сбросить активное задание онлайн-игрока. | `towers.admin` | `op` |
| `/towers wave <type>` | Создать для себя серию волн указанного типа из `wave-types`. | `towers.admin` | `op` |
| `/towers test <spawn\|central\|calibration\|chunk\|cancel\|rift\|reset\|status\|loot [type-id]>` | Тестовые действия с объектами, меню, калибровкой, волнами, разломом и лутом. | `towers.admin` | `op` |

`refresh` также принимает алиас `update`. Команда `/towers test rift remove` удаляет тестовые разломы.

## Конфигурация

Основные параметры находятся в `config.yml`:

- `weekly-quest-count`, `weekly-refresh-hours`, `weekly-refresh-time` задают число еженедельных заданий и расписание обновления. Время указывается по `Europe/Moscow` в формате `ЧЧ:ММ`.
- `calibration` задаёт число этапов, количество бумаг и настоящих бумаг на этап, а также длительность показа.
- `chunk-area` управляет размером карты секторов, размером сектора в чанках, числом волн и случайным интервалом между ними. `grid-size` ограничен размером карты 5×5; центральный сектор компьютера не используется для размещения волн.
- `wave-types` описывает доступные типы волн: вероятность выбора, мобов и их количество по волнам, эффекты, частицы и список разрешённого для типа лута. Мобы CustomMob задаются идентификаторами вида `custom:pumpkin`.
- `rift` настраивает предмет-модель, размер, высоту и дистанции разлома, режим открытия (`chunk` или `distance`), облако частиц и кадры анимации.
- `rift-loot` задаёт предметы наград, их количество и вероятность; `replaces-all: true` позволяет награде заменить остальные награды броска. `rift-scrolls.chance` задаёт общий шанс группы скроллов QUACK. Их относительные шансы задаются `weight`; в группу попадают только скроллы, перечисленные в `loot` соответствующего типа волны.
- `menus` содержит заголовки, размеры меню, названия, описания, модели предметов и размеры hitbox объектов. Модели должны соответствовать используемому ресурс-паку.
- `sounds` задаёт звуки, громкость, высоту и интервалы повторения фоновых звуков. Пустое значение отключает звук; имена пользовательских звуков должны существовать в `sounds.json` ресурс-пака.
- `messages` позволяет переопределять сообщения плагина.

После изменения конфигурации выполните `/towers reload`. Изменения `weekly-refresh-time` и `weekly-refresh-hours` пересчитывают расписание.

## Хранение данных

SQLite-файл `plugins/Towers/database.db` создаётся автоматически. Плагин использует WAL и хранит в базе прогресс игроков, расписание заданий, размещённые объекты и чанки, принудительно загруженные для работы волн. Ручное редактирование базы не требуется.

## Интеграции

PlaceholderAPI и собственная PlaceholderExpansion не реализованы. Публичные события плагина для интеграции с другими разработчиками также отсутствуют.
