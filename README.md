# Towers

Minecraft-плагин для Paper, который добавляет систему калибровочных башен,
еженедельных заданий и боевых волн, открывающихся через разломы в выбранных
чанках.

Плагин рассчитан на Paper `1.21.7+` и Java `21`.

## Возможности

- центральная башня с меню доступных еженедельных заданий;
- 16 калибровочных башен с многоэтапной мини-игрой на поиск нужных бумаг;
- компьютеры чанков и карта секторов для выбора области волн;
- разломы с анимацией открытия и закрытия, частицами, свечением и звуками;
- несколько типов волн с настраиваемыми мобами, эффектами и частицами;
- стандартные Minecraft-мобы и кастомные мобы `CustomMob`;
- награды за волны, включая обычные предметы, чертежи и QUACK-скроллы;
- сохранение заданий, дисплеев и занятых чанков в SQLite;
- асинхронная загрузка и сохранение данных игроков;
- автоматическая миграция устаревших YAML-данных в SQLite, если такие данные
  остались после предыдущей версии.

## Зависимости

### Обязательная

- [Paper](https://papermc.io/) `1.21.7` или совместимая версия API `1.21+`;
- Java `21`.

### Необязательные

- `CustomMob` — нужен для типов мобов с идентификаторами вроде
  `custom:pumpkin` и `custom:skelebass`;
- `QUACK-by-VLADMIX90` — нужен для выдачи настроенных QUACK-скроллов.

Обе зависимости указаны как soft-depend: плагин может запуститься без них,
но соответствующие типы мобов или награды будут недоступны.

## Установка

1. Установите Paper и Java `21`.
2. Соберите плагин или возьмите готовый `Towers.jar`.
3. Скопируйте `Towers.jar` в папку `plugins/` сервера.
4. При необходимости установите `CustomMob` и `QUACK-by-VLADMIX90`.
5. Запустите сервер и дождитесь создания `plugins/Towers/config.yml`.
6. Настройте конфигурацию и выполните `/towers reload` либо перезапустите
   сервер.

При первом запуске база данных создаётся в файле
`plugins/Towers/database.db`. Файл базы данных, WAL-файл и SHM-файл нельзя
удалять во время работы сервера.

## Команды

Все команды требуют разрешение `towers.admin`, которое по умолчанию выдано
операторам сервера.

### Администрирование

```text
/towers reload
/towers refresh
/towers spawn <1-16|central|computer>
/towers remove <1-16|central|calibration|chunk|all>
/towers give <player> <1-16>
/towers reset <player>
/towers wave <type>
```

- `/towers reload` — перечитывает конфигурацию, волны, дисплеи и расписание
  заданий.
- `/towers refresh` — принудительно обновляет задания игроков.
- `/towers spawn <1-16>` — создаёт калибровочную башню с указанным номером.
- `/towers spawn central` — создаёт центральную башню.
- `/towers spawn computer` — создаёт компьютер, привязанный к ближайшей
  пронумерованной башне.
- `/towers remove ...` — удаляет отдельную башню, центральную башню, группу
  объектов или все сохранённые объекты Towers.
- `/towers give <player> <1-16>` — выдаёт игроку задание на башню.
- `/towers reset <player>` — сбрасывает активное задание игрока.
- `/towers wave <type>` — запускает самостоятельную серию волн указанного
  типа для игрока.

### Тестирование

```text
/towers test spawn
/towers test central
/towers test calibration
/towers test chunk
/towers test cancel
/towers test reset
/towers test rift
/towers test rift remove
/towers test status
/towers test loot [type-id]
```

Тестовые команды предназначены для проверки меню, калибровки, выбора чанка,
разломов, состояния задания и наград. Они также требуют `towers.admin` и
должны выполняться игроком.

## Конфигурация

Основной файл — `plugins/Towers/config.yml`. После обновления плагина не
заменяйте его без необходимости: при изменении структуры лучше перенести свои
значения в свежий файл.

Основные разделы:

- `weekly-quest-count`, `weekly-refresh-hours`, `weekly-refresh-time` — число
  заданий и расписание еженедельного обновления;
- `displays` — размеры hitbox для центральной башни, калибровочных башен и
  компьютеров;
- `menus` — названия, лор, размеры меню и resource-pack model ID;
- `calibration` — количество этапов, бумаг и длительность отображения;
- `chunk-area` — размер сетки, размер сектора, количество волн и интервал между
  ними;
- `wave-types` — шансы типов волн, состав мобов, количество мобов, эффекты,
  частицы и список доступных наград;
- `rift` — внешний вид разлома, высота, дистанция открытия, режим открытия,
  облако частиц и кадры анимации;
- `rift-scrolls` и `rift-loot` — группы скроллов и обычные награды;
- `sounds` — звуки калибровки, разломов, волн и завершения заданий;
- `messages` — сообщения плагина в формате MiniMessage.

### Волны

Каждый тип в `wave-types` содержит `chance` и список `mobs`. Для каждого моба
можно задать массив `counts`, где значения соответствуют последовательным
волнам. Для кастомных мобов используется формат:

```yaml
wave-types:
  example:
    chance: 10
    mobs:
      "custom:my_mob":
        counts: [1, 2, 3]
```

Для обычных мобов используются Bukkit-имена, например `ZOMBIE`, `SKELETON` или
`PILLAGER`. Эффекты задаются через `type`, `level` и `duration`, а частицы —
через `type`, `count`, `spread`, `speed` и `interval`.

### Награды

Обычная награда в `rift-loot` задаётся `material`, `id`, диапазоном `min`/`max`
и `chance`. Параметр `replaces-all: true` делает награду исключающей остальные
награды.

QUACK-скролл описывается через `id`, `skin-id` и относительный `weight`.
Указанный `id` нужно добавить в `loot` соответствующего типа волны.

## Сборка для разработчиков

Требования:

- Java `21`;
- Maven;
- доступ к репозиторию Paper Maven.

Команды:

```bash
mvn test-compile
mvn test
mvn clean package
```

Готовый shaded JAR создаётся как:

```text
target/Towers.jar
```

Тесты используют JUnit 5, Mockito и SQLite JDBC. Paper API подключается как
`provided`, поэтому API сервера не встраивается в итоговый JAR.

## Хранение данных

Динамические данные хранятся в SQLite в `database.db` внутри папки плагина.
В базе находятся данные заданий игроков, сохранённые дисплеи и записи о
принудительно загруженных чанках. Операции с базой выполняются асинхронно, а
изменения состояния мира возвращаются в основной поток Paper.

`config.yml` предназначен только для статических настроек. Не сохраняйте в
него прогресс игроков или координаты игровых объектов.

## Разработка

Перед изменением Java-кода рекомендуется запускать полный набор тестов:

```bash
mvn test
```

После изменения Java-классов обязательна как минимум проверка компиляции:

```bash
mvn test-compile
```

При добавлении новой механики сначала добавьте или обновите соответствующие
тесты в `src/test/java`.
